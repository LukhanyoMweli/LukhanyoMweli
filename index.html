The portfolio had to be written entirely in Markdown, a lightweight markup language used widely by developers. Prior to this assessment, I had never used Markdown before and was unfamiliar with its syntax and conventions. **Task** My responsibility was to code my entire portfolio, including my Curriculum Vitae, using Markdown on GitHub. I needed to produce a well-structured, readable, and professionally formatted document that demonstrated my ability to use Markdown effectively as a communication and presentation tool. **Action** Initially, I struggled with the syntax. Simple things like creating headings, adding bullet points, and bolding text were confusing because Markdown looks different from what I was used to in tools like Microsoft Word. To overcome this, I spent time reading GitHub's documentation on GitHub Flavoured Markdown (GFM) and experimenting directly in my repository. I practised by writing small sections of my CV and previewing them on GitHub to see how they rendered. Through trial and error, I gradually became more comfortable with the language and began to understand its logic and structure. **Result** By the end of the process, I had successfully coded a complete, well-structured CV and portfolio page using Markdown. I developed a new technical skill that is widely used in the software development industry. I now understand why developers rely on Markdown for README files, documentation, and communication on platforms like GitHub. This experience improved both my technical ability and my confidence in learning new tools independently. --- ## 🎤 Reflection: Mock Interview Experience (STAR Method) **Situation** As part of my work readiness training at CPUT, I was required to participate in a mock job interview to prepare for entering the professional world as a software developer. The purpose was to simulate a real interview environment and demonstrate my ability to present myself, communicate my skills, and respond to interview questions confidently. **Task** I needed to prepare for and record a mock interview that would be embedded in my digital portfolio. The interview had to reflect my professional readiness, my understanding of my field, and my ability to articulate my skills, experience, and goals to a potential employer. **Action** To prepare, I researched common interview questions for ICT and software development roles, particularly around Java development, projects I had completed, and my career goals. I practised answering questions out loud beforehand to build fluency and reduce nervousness. On the day of the recording, I dressed professionally, chose a clean and quiet environment, and focused on speaking clearly and confidently. I structured my answers to highlight my technical skills and my enthusiasm for software development. **Result** The mock interview went well and I felt confident throughout. Recording the experience and embedding it in my portfolio gave me a tangible piece of evidence of my communication and professional skills. More importantly, the process made me realise the importance of preparation in an interview setting. I now feel significantly more ready to face a real job interview and understand how to present myself effectively to potential employers in the ICT industry. --- ## 🌐 Reflection: Using GitHub Pages (STAR Method) **Situation** As part of the digital portfolio assessment, I was required to deploy my portfolio as a live, publicly accessible website using GitHub Pages. This was a new experience for me as I had previously only used GitHub for storing and managing code, and had never deployed a live website through it before. **Task** My task was to configure my GitHub repository so that my Markdown portfolio would be published as a live website that anyone could access via a URL. This required me to understand how GitHub Pages works and ensure that my content rendered correctly in a browser. **Action** I began by exploring the GitHub Pages settings within my repository. While the process was not entirely clear to me at first, I worked through it step by step — enabling GitHub Pages through the repository settings and selecting the correct branch to deploy from. Even though I was not fully certain about every step, I persisted and kept checking whether my site had gone live by visiting the URL. I also tested the site on my phone browser to confirm it was accessible and displaying correctly. **Result** Despite my uncertainty, I successfully deployed my portfolio to GitHub Pages and it is now live and publicly accessible. This was a significant achievement as it meant my portfolio was no longer just a collection of files on GitHub but a real, professional-looking website. The experience taught me that deploying web content is an essential skill for any developer, and although I still have more to learn about GitHub Pages, I now have the foundational knowledge and confidence to build on going forward. --- ## 📄 Curriculum Vitae [View My Full CV](https://lukhanyomweli.github.io/LukhanyoMweli/cv.md) --- ## 💻 Projects - **Medication Management System** Java Maven application with CRUD functionality using Derby database - **Student System** Java-based system for managing student data - **Payroll Application** Application for managing employee salary data --- *© 2026 Lukhanyo Mweli | CPUT — Faculty of Informatics and Design* **Result** By the end of the process, I had successfully coded a complete, well-structured CV and portfolio page using Markdown.
